# 사내 도서 대여 서비스 요구사항

기획 목표: 기획서와 일부 화면 시안으로 구현 Task 목록까지 만든다. 용어는 `glossary.md` 를 따른다.

## 1. 입력별 요약

### 1.1 기획서 v0.3
- 사내 서가를 종이 대장으로 관리해 누가 무엇을 빌렸고 언제 돌려주는지 알기 어렵고, 분실과 장기 미반납이 잦다.
- 목표는 임직원이 웹에서 도서를 찾고 빌리고 반납하는 것, 관리자가 도서를 등록하고 연체를 확인하는 것이다.
- 1차 오픈은 검색·대여·반납·내 대여 현황까지이고, 관리자 기능과 연체 알림은 2차다.
- 사용자는 회사 계정으로 로그인하는 임직원(회원가입 없음)과 총무팀 2명의 관리자다.
- 제약은 사내망 전용, 모바일 브라우저 지원, 개인정보는 이름·부서·회사 메일만, 1차 오픈 6주다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §1~§6`

### 1.2 로그인 화면 시안
- 상단에 서비스 이름 「사내 도서 대여」, 제목 「로그인」, 안내 「회사 계정으로 로그인하세요」가 있다.
- 입력 칸은 「회사 계정(사번 또는 메일)」과 「비밀번호」 둘이고 예시로 `user1@example.com` 이 보인다.
- 주 버튼 「로그인」 아래에 「로그인 문제는 IT 지원(내선 `<IT 지원 내선>`)에 문의하세요」 문구가 있다.
- 실패 시 안내 문구는 기획서 §4 1 이 요구하나 시안에는 실패 상태가 없다. 오른쪽이 잘려 있다(11절).
- 근거: `in/planning/m5/mockup-login.png@251c22d8aace`

### 1.3 도서 검색 목록 시안
- 상단 제목 「도서 검색」, 「제목 또는 저자」 입력 칸과 「검색」 버튼이 있다.
- 결과 한 줄은 표지 자리, 제목, 저자, 상태 표시로 이루어진다. 예시 4건이 있다.
- 상태 표시는 「대여 가능 N권」(초록)과 「모두 대여 중」(빨강) 두 모양이다.
- 결과 0건 상태, 결과 항목을 눌렀을 때의 이동, 화면 아래쪽 이동 수단은 시안에 없다. 오른쪽이 잘려 있다(11절).
- 근거: `in/planning/m5/mockup-search.png@c9a286d2f29b`, `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 2

## 2. 문제

사내 서가는 종이 대장으로 관리되어 지금 누가 어떤 도서의 어느 권을 빌렸는지, 언제 돌려줄 예정인지 알기 어렵다. 그 결과 분실과 장기 미반납이 잦다. 임직원은 서가에 가 봐야 대여 가능한지 알 수 있고, 관리자는 연체자를 가려내기 어렵다.

- 1차가 해결하는 문제: 임직원이 서가에 가지 않고도 남은 권(대여 가능 권수)과 내 반납 예정일을 확인할 수 있고, 모든 대여와 반납이 서비스에 기록되어 종이 대장을 대신한다. 연체 중인 사람은 반납하기 전까지 새로 빌릴 수 없다.
- 2차로 남는 문제: 관리자가 연체자를 가려내는 일(연체 목록)과 연체를 알리는 일(메일 알림). 1차에서 연체는 임직원 본인의 내 대여 현황에만 표시된다.
- 1차에서 다루지 않는 문제: 분실. 분실된 권을 표시하거나 처리하는 수단은 1차에 없다(7절).

근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §1`, 결정 로그 seq 3 (`S1-Q3`)

## 3. 해결

임직원이 사내망의 웹(모바일 브라우저 포함)에서 회사 계정으로 로그인해 도서를 검색하고, 권별 대여 가능 여부를 보고, 즉시 대여하고, 내 대여 현황에서 반납 예정일·연체 여부를 확인하고 반납한다. 연체 중이면 반납하기 전까지 새 대여가 막힌다. 모든 대여와 반납이 서비스에 기록되어 대장을 대신한다.

- 1차에서 해결되는 것: 남은 권과 반납 예정일의 확인, 대여·반납 기록, 연체 중 새 대여 제한.
- 2차로 남는 것: 관리자의 도서 등록·수정, 관리자의 연체자 확인(연체 목록), 연체 메일 알림.
- 1차에는 총무팀(관리자)이 서비스에서 할 수 있는 일이 없다.
- 분실은 1차에서 다루지 않는다.
- 1차의 도서·권 데이터는 개발팀이 처음에 적재하고 이후 변경은 개발팀에 요청한다.
- 입력에 없어 임시값으로 정한 것: 로그인 유지 시간(8시간), 지원 브라우저와 최소 화면 폭, 검색의 세부 규칙, 성능·동시 사용자 수, 회사 계정 시스템 무응답 기준(10초)은 입력에 근거가 없는 임시값이다. 9절 가정 표의 해당 행에서 바꿀 수 있다.

근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §2`, `§4`, 결정 로그 seq 1·3 (`S1-Q1`·`S1-Q3`)

## 4. 사용자 스토리

### 4.1 1차

**US-01 로그인한다 (임직원)**
임직원으로서 회사 계정(사번 또는 회사 메일과 비밀번호)으로 로그인해 서비스를 쓰고 싶다.
- 정상 흐름: 로그인 화면에서 회사 계정과 비밀번호를 입력하고 「로그인」을 누른다. 인증이 되면 도서 검색 화면으로 간다.
- 정상 흐름: 로그아웃 버튼으로 로그아웃할 수 있다. 로그인은 8시간 유지된다(임시값).
- 예외 흐름: 계정 칸이나 비밀번호 칸이 비어 있으면 로그인을 진행하지 않고 어느 칸이 비었는지 안내한다.
- 예외 흐름: 로그인하지 않은 채 다른 화면 주소로 들어오면 로그인 화면으로 보낸다.
- 예외 흐름: 로그인 유지 시간이 지난 뒤 대여나 반납을 누르면 그 처리는 하지 않고 로그인 화면으로 보낸다. 다시 로그인한 뒤 직접 다시 눌러야 한다.
- 로그인 화면에는 로그인 문제를 문의할 IT 지원 내선 안내가 있다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §3`·`§4` 1, `in/planning/m5/mockup-login.png@251c22d8aace`

**US-02 비밀번호를 새로 만들지 않고 회사 계정으로 들어온다 (임직원)**
임직원으로서 이 서비스용 비밀번호를 새로 만들거나 가입하지 않고, 내 회사 계정 그대로 들어오고 싶다.
- 로그인 방식은 시안대로 이 서비스 화면에서 사번(또는 메일)과 비밀번호를 받아 회사 계정 시스템으로 확인하는 것이다. 서비스는 비밀번호를 저장하지 않는다.
- 정상 흐름: 입력한 회사 계정이 인증되면 이름·부서·회사 메일만 받아 임직원으로 식별한다. 임직원은 회사 메일로 구분하고 사번은 저장하지 않는다. 새 비밀번호를 만들거나 가입 절차를 거치지 않는다.
- 정상 흐름: 로그인할 때 받은 이름·부서가 저장된 값과 다르면 저장값을 받은 최신 값으로 바꾼다(A-32).
- 예외 흐름: 인증이 실패하면(계정 없음·비밀번호 틀림) 입력 칸은 그대로 두되 비밀번호 칸은 비우고, 안내 문구를 보인다. 문구에는 무엇이 잘못됐는지(계정 또는 비밀번호가 맞지 않음 — 어느 쪽인지는 알려 주지 않는다)와 다음에 할 일(다시 입력, 계속되면 IT 지원 문의)이 들어간다.
- 예외 흐름: 회사 계정 시스템이 10초 안에 응답하지 않으면(A-31, 임시값) 무응답으로 보고 로그인하지 않는다. 안내 문구에는 무엇이 안 됐는지(회사 계정 확인을 하지 못함)와 다음에 할 일(다시 시도, 계속되면 IT 지원 문의)이 들어간다.
- 예외 흐름: 인증은 되었으나 받지 못한 값이 있을 때, 이름·부서가 없으면 비워 두고 허용하고 회사 메일이 없으면 허용하지 않는다(A-13).
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §3`·`§4` 1·`§6`, 결정 로그 seq 2·4 (`S1-Q2`·`S1-Q4`)

**US-03 (삭제 — NFR-03·NFR-04 로 내림)**
개인정보 최소 보관과 비밀번호 비보관은 사용자가 직접 하는 일이 아니라 서비스가 지킬 제약이라 NFR-03·NFR-04 로 옮겼다. 번호 US-03 은 다시 쓰지 않는다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §6`

**US-04 도서를 찾는다 (임직원)**
임직원으로서 제목이나 저자 일부만 입력해도 도서를 찾고, 결과에서 바로 대여 가능 여부를 보고 싶다.
- 정상 흐름: 「제목 또는 저자」 칸에 글자를 넣고 「검색」을 누르면 제목이나 저자에 그 글자가 들어간 도서가 목록으로 나온다. 한 줄에 표지, 제목, 저자, 「대여 가능 N권」 또는 「모두 대여 중」이 있다. 대소문자는 구분하지 않고 앞뒤 공백은 무시한다(A-22).
- 정상 흐름: 검색어를 비우거나 공백만 넣고 「검색」을 누르면 전체 도서를 보여 준다(공백만 입력은 빈 검색어와 같다).
- 정상 흐름: 결과는 한 쪽에 20건씩 나눠 보인다. 결과가 20건을 넘으면 「다음」으로 다음 쪽의 다음 20건을 본다. 마지막 쪽에서는 「다음」을 비활성으로 하거나 보이지 않게 하고, 마지막 쪽의 건수는 남은 건수만큼이다(20건 미만일 수 있다).
- 정상 흐름: 검색어가 100자를 넘으면 100자에서 잘라 검색한다(A-22).
- 예외 흐름: 결과가 0건이면 「검색 결과가 없습니다」 문구와 다음에 할 일(다른 검색어로 다시 검색, 또는 검색어를 비워 전체 도서 보기)을 보인다.
- 예외 흐름: 검색 중 서버 오류나 네트워크 실패가 나면 결과 목록 대신 안내 문구를 보인다. 문구에는 무엇이 잘못됐는지(검색하지 못함)와 다음에 할 일(다시 검색, 계속되면 IT 지원 문의)이 들어가고, 이전 결과를 새 검색의 결과인 것처럼 남겨 두지 않는다.
- 예외 흐름: 표지가 없는 도서는 시안의 회색 자리 모양으로 대신 보인다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 2, `in/planning/m5/mockup-search.png@c9a286d2f29b`

**US-05 목록에서 대여 가능 여부를 구분해 본다 (임직원)**
임직원으로서 대여 가능한 도서와 모두 대여 중인 도서를 한눈에 구분하고 싶다.
- 정상 흐름: 대여 가능 권이 있으면 「대여 가능 N권」, 하나도 없으면 「모두 대여 중」으로 보인다.
- 예외 흐름: 다른 사람이 방금 마지막 권을 빌렸으면 다음 갱신 때 「모두 대여 중」으로 바뀐다. 갱신은 화면을 열 때, 새로고침할 때, 검색을 실행할 때다(자동으로 바뀌지는 않는다).
- 근거: `in/planning/m5/mockup-search.png@c9a286d2f29b`, `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 2

**US-06 도서 상세를 본다 (임직원)**
임직원으로서 도서의 표지, 저자, 출판사, 소개와 권별 상태를 보고 빌릴지 정하고 싶다.
- 정상 흐름: 검색 목록에서 도서를 선택하면 도서 상세가 열리고, 권마다 「대여 가능」 또는 「대여 중」이 보인다.
- 예외 흐름: 도서가 없어졌거나 주소가 잘못되면 「도서를 찾을 수 없습니다」 문구(무엇이 잘못됐는지)와 검색 화면으로 돌아가는 버튼(다음에 할 일)을 보인다.
- 예외 흐름: 서버 오류나 네트워크 실패로 도서 상세를 불러오지 못하면 「도서 정보를 불러오지 못했습니다」 문구(무엇이 잘못됐는지)와 다시 불러오기 버튼, 검색 화면으로 돌아가는 버튼(다음에 할 일)을 보인다. 불러오지 못한 화면에서는 「대여」를 할 수 없다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 3 (시안 없음 — §5)

**US-07 도서를 빌린다 (임직원)**
임직원으로서 대여 가능한 도서를 신청 즉시 빌리고 반납 예정일을 알고 싶다.
- 정상 흐름: 도서 상세에서 대여 가능 권이 있고 내가 연체 중이 아닌 상태로 「대여」를 누르면 대여 가능 권 하나가 즉시 내게 대여되고, 그 권은 「대여 중」이 된다. 반납 예정일은 대여일 + 14일이다(날짜 예시는 A-25). 결과는 내 대여 현황에서 볼 수 있다.
- 예외 흐름: 모든 권이 대여 중이면 「대여」 버튼은 비활성이고 이유(모든 권이 대여 중)를 안내한다. 예약은 없다.
- 예외 흐름: 내가 연체 중이면 새 대여를 할 수 없다. 「대여」 버튼은 비활성이고, 누르는 시점에 연체가 된 경우처럼 처리 때 연체가 확인되면 그 대여는 거절한다. 안내 문구에는 무엇이 잘못됐는지(연체 중인 도서가 있어 새로 빌릴 수 없음)와 다음에 할 일(내 대여 현황에서 연체 도서를 반납한 뒤 다시 빌리기)이 들어가고, 내 대여 현황으로 가는 버튼을 함께 보인다. 연체 도서를 모두 반납하면 곧바로 다시 빌릴 수 있다.
- 예외 흐름: 화면을 보는 사이 마지막 권을 다른 사람이 먼저 빌렸으면 대여를 거절하고 안내 문구를 보인다. 문구에는 무엇이 잘못됐는지(방금 모든 권이 대여 중이 됨)와 다음에 할 일(도서 상세나 검색 화면으로 돌아가 다른 도서 찾기)이 들어간다. 한 권이 두 사람에게 대여되는 일은 없다.
- 예외 흐름: 같은 제출은 한 번만 처리한다. 「한 제출」은 화면이 제출마다 발급하는 요청 식별자가 같은 요청이다. 대여 가능 2권 이상인 도서에서 같은 제출(같은 요청 식별자)을 연달아 두 번 보내도 대여는 1건만 생기고 대여 가능 권수는 1만 줄어든다. 두 번째 응답은 첫 번째 처리 결과를 그대로 보여 준다.
- 예외 흐름: 이미 열려 있던 화면을 닫고 새로 연 화면에서 의도적으로 하는 두 번째 대여는 새 요청 식별자를 받으므로 별개의 대여다. 이미 빌린 같은 도서를 또 빌리는 것은 막지 않는다(A-07).
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 4, 결정 로그 seq 3 (`S1-Q3`)

**US-08 대여 결과를 확인한다 (임직원)**
임직원으로서 대여가 끝나면 무엇을 언제까지 돌려줘야 하는지 곧바로 확인하고 싶다.
- 정상 흐름: 대여가 성립하면 도서 제목과 반납 예정일을 보여 준다.
- 예외 흐름: 대여 처리 중 서버 오류나 네트워크 실패가 나면 무엇이 잘못됐는지(대여가 되지 않았거나 결과를 확인하지 못함)와 다음에 할 일(내 대여 현황에서 확인한 뒤 필요하면 다시 대여)을 안내한다. 반쯤 처리된 상태는 남기지 않는다. 즉 권은 「대여 중」인데 내 대여 현황에는 없는 상태, 또는 그 반대가 되지 않는다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 4·5

**US-09 내 대여 현황을 본다 (임직원)**
임직원으로서 내가 지금 빌린 도서와 반납 예정일을 한곳에서 보고 싶다.
- 정상 흐름: 내 대여 현황에 내가 빌려 아직 반납하지 않은 권마다 도서 제목, 반납 예정일, 연체 여부가 나온다. 한 줄은 대여 한 건이다. 같은 도서의 두 권을 빌렸으면 두 줄이 나온다.
- 예외 흐름: 서버 오류나 네트워크 실패로 현황을 불러오지 못하면 「대여 현황을 불러오지 못했습니다」 문구(무엇이 잘못됐는지)와 다시 불러오기 버튼(다음에 할 일)을 보인다. 이때 빈 목록(「빌린 도서가 없습니다」)을 대신 보이지 않는다.
- 예외 흐름: 빌린 도서가 없으면 「빌린 도서가 없습니다」 문구와 도서 검색 화면으로 가는 버튼(다음에 할 일)을 보인다.
- 예외 흐름: 다른 임직원의 대여 현황은 보이지 않는다. 다른 임직원의 현황을 보려고 직접 주소를 입력해도 「접근할 수 없습니다」 안내가 나오며, 주소를 입력했을 때와 화면으로 들어갔을 때 결과가 같다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 5 (시안 없음 — §5)

**US-10 연체를 알아본다 (임직원)**
임직원으로서 반납 예정일이 지난 도서를 바로 알아보고 서둘러 반납하고 싶다.
- 정상 흐름: 반납 예정일이 지났는데 반납하지 않은 권은 내 대여 현황에서 「연체」로 구별되어 보인다. 반납 예정일 당일은 연체가 아니다(날짜 예시는 A-25).
- 정상 흐름: 연체 중인 권이 하나라도 있으면 내 대여 현황 위쪽에 연체 중이라 새로 빌릴 수 없고 연체 도서를 반납하면 다시 빌릴 수 있다는 안내를 보인다.
- 예외 흐름: 연체 중이어도 반납은 막지 않는다. 연체 중인 사람의 새 대여는 막는다(US-07).
- 1차에는 연체 알림이 없다.
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §1`·`§2`·`§4` 5, 결정 로그 seq 3 (`S1-Q3`)

**US-11 도서를 반납한다 (임직원)**
임직원으로서 도서를 서가에 돌려놓고 내 대여 현황에서 반납 처리를 하고 싶다.
- 정상 흐름: 내 대여 현황에서 반납할 권의 「반납」을 누르고 반납 확인 단계에서 확정하면 그 권이 「대여 가능」으로 돌아가고 내 대여 현황에서 사라진다. 연체 중이던 권도 같다. 반납은 눌린 그 한 건만 처리한다. 같은 도서의 두 권을 빌려 두 줄이 있을 때 한 줄을 반납하면 그 건만 반납되어 사라지고 다른 줄은 그대로 남으며, 다른 한 줄도 따로 반납하면 각각 대여 가능으로 돌아가 대여 가능 권수가 총 2 늘어난다.
- 예외 흐름: 반납 확인 단계에서 취소하면 아무것도 바뀌지 않는다.
- 예외 흐름: 반납 처리 중 서버 오류나 네트워크 실패가 나면 무엇이 잘못됐는지(반납이 되지 않았거나 결과를 확인하지 못함)와 다음에 할 일(내 대여 현황을 다시 불러와 확인한 뒤 필요하면 다시 반납)을 안내한다. 반납이 확인되기 전까지 그 권의 상태는 「대여 중」 그대로이고, 권 상태와 내 대여 현황이 어긋난 채 남지 않는다(권은 대여 가능인데 현황에는 남아 있거나, 그 반대가 되지 않는다).
- 예외 흐름: 이미 반납된 권을 다시 반납하려 하면(여러 창에서 눌렀을 때 등) 이미 반납되었다고 안내하고 중복 처리하지 않는다.
- 예외 흐름: 다른 사람이 빌린 권은 반납 처리할 수 없다. 「접근할 수 없습니다」 안내가 나오고, 직접 주소를 입력해 처리하려 해도 같은 결과다.
- 실물 확인은 하지 않는다(7절).
- 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §4` 6, `§5`(반납 확인 화면 시안 없음)

## 7. 범위 밖

1차 오픈에 포함하지 않는다. 두 부류다. 입력이 직접 2차로 뺀 것과, 입력에 없어 이번에 의식적으로 뺀 것이다.

### 7.1 입력이 2차로 뺀 것

- 관리자 도서 등록·수정 (F-11, US-12) — `in/planning/m5/library-spec.md@7f3d2fb6fa6c §2`·`§4` 7
- 연체 목록 확인 (F-12, US-13) — `in/planning/m5/library-spec.md@7f3d2fb6fa6c §2`·`§4` 8
- 연체 메일 알림 (F-13, US-14) — `in/planning/m5/library-spec.md@7f3d2fb6fa6c §2`·`§4` 8

### 7.2 이번에 의식적으로 뺀 것

입력에 없어 이번에 하지 않기로 한 것이다. 바꾸려면 피드백으로 적어 다시 생성한다.

- 예약 (A-06)
- 대여 연장 (A-11)
- 1인당 대여 권수 한도 (A-04)
- 실물 반납 확인 절차 (A-10)
- 분실·파손된 권을 표시하거나 처리하는 일 (권 상태는 「대여 가능」·「대여 중」 둘뿐이다)
- 자체 회원가입 (A-27)
- 본인 과거 이력 조회: 1차의 내 대여 현황은 지금 빌린 권만 보인다(입력 §4 5). 반납을 마친 과거 이력을 본인이 보는 화면은 입력에 없어 이번에 두지 않는다. 기록은 F-14 로 보관되므로 2차 이후에 정할 수 있다.

## 8. 아직 특정 못 한 것

범위 안인데 아직 못 정한 것이다.

- 회사 계정 시스템의 연동 방식과, 인증 때 이름·부서·회사 메일을 받을 수 있는지: 로그인 방식은 확정(A-27)이지만 회사 계정 시스템이 무엇이고 어떻게 연동하는지는 입력에 없다. 뒤 단계(아키텍처)에서 정하며 문서로 판정되지 않으면 스파이크 대상이다. 회사 메일을 받을 수 없으면 임직원 구분(A-29)이 성립하지 않으므로 이 확인이 가장 중요하다.
- 1차 도서·권 데이터의 규모(도서 수, 권 수)는 입력에 없다. 규모가 정해지지 않으면 테스트용 자리표시자 도서로 채워 확인한다(A-26).
- 도서 상세, 내 대여 현황, 반납 확인 화면의 모양(시안 없음 — 11절).
- 도서·권 데이터 변경 요청(A-26)을 받는 개발팀 담당자와 처리에 걸리는 시간: 입력에 없다.
- 알려진 한계: 회사 메일이 바뀌면(개명·메일 규칙 변경 등) 서비스는 다른 임직원으로 취급하므로 이전 대여 기록과 끊긴다. 임직원 구분을 회사 메일로 정했기 때문이다(A-29).

## 11. 기타

- 시안 잘림: 로그인 시안과 검색 시안 모두 오른쪽이 잘려 있다(내보내기 폭 한계로 보인다). 입력 칸·버튼·상태 표시가 오른쪽 끝까지 어떻게 이어지는지, 오른쪽 가장자리에 다른 요소(메뉴·아이콘 등)가 있는지 확인할 수 없다. 보이는 부분 외의 것은 요구사항으로 삼지 않았다. 근거: `in/planning/m5/mockup-login.png@251c22d8aace`, `in/planning/m5/mockup-search.png@c9a286d2f29b`
- 시안 없는 화면: 도서 상세, 내 대여 현황, 반납 확인, 관리자 화면은 시안이 없다. 1차 화면 중 앞 셋은 S2 에서 새로 설계가 필요하다. 근거: `in/planning/m5/library-spec.md@7f3d2fb6fa6c §5`
- 시안 속 문구: 로그인 시안의 IT 지원 내선 번호는 실제 번호처럼 보일 수 있어 이 문서에서는 `<IT 지원 내선>` 으로 적었다. 실제 번호는 구현 때 총무팀 또는 IT 지원에서 받는다.
- 시안 속 예시 메일 `user1@example.com` 은 이미 자리표시자다. 도서 예시(「클린 코드」등)는 실제 개인정보가 아니라 도서 데이터 예시다.
- 시안 속 로그인 비밀번호 칸의 점 표시는 입력 예시일 뿐 값이 아니다.
- 입력 안 지시문 — 요구사항 아님: 없음.
- 입력 문서는 v0.3 이고 시안이 일부뿐이라 요구사항은 이후 기획서가 바뀌면 다시 만든다.
