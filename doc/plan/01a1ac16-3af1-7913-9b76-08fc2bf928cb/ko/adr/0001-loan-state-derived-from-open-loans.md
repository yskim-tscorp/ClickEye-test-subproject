# ADR 0001 대여 중 상태를 저장하지 않고 열린 대여 건에서 유도한다

## 결정

권의 「대여 중」 상태를 따로 저장하지 않고 「반납일이 비어 있는 대여 건이 있다」로 정의한다. 권당 열린 대여 건이 하나를 넘지 못하게 DB 의 부분 유일 인덱스(반납일이 비어 있는 건에만 거는 권별 유일 제약)로 막는다. 연체와 대여 가능 권수도 저장하지 않고 읽을 때 계산한다(결정 id S3-D1).

## 이유

- 상태와 대여 기록이 한 곳에서 나오므로 어긋날 수 없고, 권은 「대여 중」인데 내 대여 현황에는 없는 식의 반쯤 처리된 상태가 구조상 생기지 않는다(`plan/requirements.md#US-08`, `plan/requirements.md#US-11`).
- 한 권이 두 사람에게 동시에 나가지 않는다는 요구를 코드가 아니라 DB 제약이 지킨다(`plan/requirements.md#NFR-06`).
- 2차 기능(연체 목록)은 새 읽기 연산으로 붙고 대여·반납 흐름을 고칠 필요가 없다. 대여 연장·예약은 새 연산과 상태가 필요해 모듈 수정이 있다.
- 되돌리기 어렵고(데이터 모델의 뼈대), 권 상태 컬럼을 두는 일반적인 방식과 달라 맥락 없이는 놀랍고, 실제 대안 사이의 트레이드오프였다.

## 고려한 대안

- B — 권 상태를 저장하고 행 잠금으로 보호: 규칙이 한 파일에 모이는 장점이 있으나 상태와 대여 행을 함께 갱신해야 해 어긋날 자리가 남는다(`work/core-design-B.md#2. 내부 구조와 동시성 제어`).
- C — 저장소를 포트로 빼고 메모리 어댑터를 둠: 규칙 시험은 DB 없이 되지만 동시성 성질은 메모리에서 시험할 수 없고 간접 층이 늘어난다(`work/core-design-C.md#3. 깊이·지역성·seam 과 어댑터 수`).

## 결과와 대가

- 대여 가능 권수를 세는 읽기가 검색 쪽에 생겨 도서 20건마다 열린 대여 건을 확인한다. 동시 사용자 50명 미만이라 3초 안에 처리할 수 있다고 보며 동시성은 스파이크 S3-D11 로 확인한다.
